# Backlog

This file lists every feature that is visible in the app but not working yet, and everything that
was deferred or skipped. Two rules from the [brief](BRIEF.md) put it here:

- Brief §6: features that are not implemented yet stay visible exactly as designed but disabled,
  with the tooltip "Available in a future version", and get an entry in this file.
- Brief §9: nothing is silently skipped. Anything left out of a milestone is logged here.

[ROADMAP.md](ROADMAP.md) checks both in every milestone: gate S9 (honest UI) and exit check E5
(backlog complete).

Related: [roadmap](ROADMAP.md) · [design inventory](DESIGN_INVENTORY.md) ·
[design gaps](DESIGN_GAPS.md) · [questions](QUESTIONS.md) · [progress](PROGRESS.md)

## What goes here

- Every entry point that is visible but disabled: tools, menu items, quick tools, palette commands,
  settings options and panes.
- Every drawn screen or state that is deferred to a later milestone.
- Every placeholder that stands in for a missing answer or asset, such as a default kept while an
  owner question in [QUESTIONS.md](QUESTIONS.md) is open.
- Every check the development container and CI cannot run (hardware, arm64 builds, screen readers,
  native-speaker review), with its pending owner check in [PROGRESS.md](PROGRESS.md#pending-owner-checks).
- Every string in a goldened screen that falls back to English because its translation is missing.
- Every test case or check that was skipped, with the reason.

Not here: open questions for the owner ([QUESTIONS.md](QUESTIONS.md)), conflicts and gaps in the
design ([DESIGN_GAPS.md](DESIGN_GAPS.md)), and bugs (GitHub issues).

## Rules

- Add the entry in the same commit that disables, defers or skips the item. A visible entry point
  also gets a value in the feature registry that names the row (below).
- Ids run B001, B002 and so on. They are never reused.
- When the item ships, remove its disabled state, move its row to [Done](#done) with the milestone
  it shipped in, and commit both together. A feature ships by leaving the registry: delete its
  value, and the compiler lists every control that still names it.
- One feature registry in Dart drives every disabled state ([ROADMAP.md](ROADMAP.md) gate S9,
  approved by the owner on 2026-10-16, built in M2's first commit): the `Feature` enum in
  `app/lib/app/feature_registry.dart` holds the features that are visible but do not work yet, each
  with its row id, such as `scanToPdf('B021')`, and every disabled control takes its "Available in a
  future version" from its value. `tools/checks` `feature_registry` fails when a value has no open
  row here (a row under Done means the feature shipped and its value must go), a value names no
  control, or a screen passes the reason without the registry. A feature whose entry points ship at
  different times is split into a value and a row per part first. Rows without an entry point of
  their own (deferred states, skipped checks, keys only) have no value. Desktop drops shipped
  (B010, Done) and need none; a1-6's disabled "Combine into one PDF" target has `combineDropped`
  (B191).

## Entry format

| Field | Content |
|---|---|
| ID | B001, B002, … |
| Feature | what is disabled, deferred or skipped |
| Artboards | the board ids that draw it, from [DESIGN_INVENTORY.md](DESIGN_INVENTORY.md) |
| Where it appears disabled | the exact place in the app, for example "Start › quick tools › Compare"; "not visible" for deferred states and skipped checks |
| Target milestone | the milestone that will make it work (M1 to M5, P2 to P5), with a link to the question if it depends on one |
| Notes | the reason, related design gaps or questions, and anything the next person needs |

Example of a row, for illustration only:

```markdown
| B001 | Compare documents | a9-2, a9-2b | Start › quick tools › Compare; Tools row › Compare | P3 | Compare is phase 3 (brief §7) |
```

## Open

M1 added the disabled shell, start-screen and settings items in the same commits that disabled
them. The first entries came from the casing and region-format utilities (phase F4); B006 and
B007 came from the bridge and PDFium bundling work (phases E3 and E4), B008 and B009 from the title
bars (phase H1), B010 to B017 from the component library (phase G), B018 to B092 from the
shell, first run, the start screen and Settings (phases H2 to H5 and I2 to I4), and B093 to B096 from
narrow windows (phase H6), B097 and B098 from the golden comparison (phase K2), and B099 and B100 from closing M1 (phase L).
B101 to B106 come from the [M2 plan](PROGRESS.md#m2-plan) (phase 0 of M2): they record decisions
that are Proposed with the plan, and change if the owner decides otherwise. B109 comes from the
API commit of M2.

In "Where it appears disabled", keys in parentheses are the control's keys in the shortcut table
(`app/lib/features/shell/shortcuts.dart`). They do nothing until the feature ships: a command without
a handler is disabled, so its keys pass through (`ShellCommandAction`). "Keys only" marks a command
that no control shows. Where only macOS keys are given, Windows and Linux use Ctrl for ⌘, Alt for ⌥
and Shift for ⇧.
