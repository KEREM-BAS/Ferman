# Flutter rules

These rules apply to the Flutter app, the token generator and the design-reference renderer. Everything in [CLAUDE.md](../../CLAUDE.md) still applies. Background: [brief §6](../../docs/BRIEF.md#6-flutter-conventions), [ARCHITECTURE.md §2.5](../../docs/ARCHITECTURE.md#25-flutter-app-layout) and [ADR 0011](../../docs/adr/0011-flutter-state-navigation-components.md).

## Toolchain and packages

- Flutter 3.47.7 with Dart 3.13.5. Node 24.22.0 LTS and playwright-core 1.56.1 only for `tools/design-refs` (the pin matches the Chromium revision 1194 preinstalled in the development container; CI uses the same revision). Never run the Playwright installer (`npx playwright-core install`): it also downloads Playwright's ffmpeg build (LGPL-2.1). CI downloads the revision 1194 headless shell directly (`tools/design-refs/fetch-chromium.sh`, SHA-256 pinned from the first CI download) and passes its path with `--chromium`.
- State: flutter_riverpod 3.4, riverpod_annotation 4 and riverpod_generator 4, run by build_runner. Providers use `@riverpod`.
- Lints: very_good_analysis 11 plus riverpod_lint 3.1.9 as an analyzer plugin under `plugins:` in `analysis_options.yaml`. Do not add custom_lint. Run both `flutter analyze` and `dart analyze --fatal-infos`: the plugin's diagnostics appear only in `dart analyze`.
- Constructors use Dart 3.13's `new` form (`const new(...)`, `new(...)`, `new name(...)`), because very_good_analysis 11 enforces `unnecessary_type_name_in_constructor`. Callers still write `ClassName(...)`.
- Navigation: go_router 18. Modes, document tabs and sidebar tabs are state, not routes.
- Goldens: alchemist. Do not use golden_toolkit (discontinued).
- Desktop and assets: window_manager, path_provider, path_parsing (icon path data), desktop_drop (from M2; its MPL-2.0 `dbus` dependency was approved in [Q17](../../docs/QUESTIONS.md#q17), ships unmodified with its notice and is skipped by name in the licence check), file_selector (M2, [ADR 0018](../../docs/adr/0018-native-file-pickers.md)). Localization: intl and flutter_localizations. Never flutter_svg or vector_graphics: both depend on `http`, which the network deny list forbids.
- flutter_rust_bridge 2.13.0, the same version as the Rust crate and the codegen. Regenerate the bindings with `(cd app && flutter_rust_bridge_codegen generate) && cargo fmt -p ferman-api` (codegen 2.13.0 needs cargo-expand 1.0.127); CI fails on any diff.
- `app/rust_builder/` is the FFI plugin `rust_lib_ferman`: it builds ferman-api through cargokit, vendored from the flutter_rust_bridge 2.13.0 template with two changes marked "Ferman patch" (listed in its README). It is its own package, left out of analysis in `analysis_options.yaml`; keep any further change marked the same way.
- Desktop builds and `flutter test integration_test` need PDFium: run `bash tools/pdfium/fetch.sh --platform <linux-x64|win-x64|mac-univ>` first. The Linux and Windows CMake files stop at configure time without it, and the macOS Bundle Framework phase copies it from `build/pdfium/mac-univ/`.
- No GetX in any form. No networking, font-downloading (google_fonts), analytics or crash-reporting packages.
- Every new package goes into [DEPENDENCIES.md](../../docs/DEPENDENCIES.md) with its licence and passes `very_good packages check licenses`.

## Engine boundary

- The UI never touches PDF internals. It calls only ferman-api through flutter_rust_bridge.
- Feature code reaches the engine only through the services and providers in `app/lib/engine/`. Only `app/lib/engine/` imports `app/lib/bridge/`: `tools/checks` `bridge_imports` fails on any other import or export of it in `app/lib/`, `app/test/` or `app/integration_test/`, relative and conditional URIs included.
- The engine library is opened by absolute path beside the running executable (`bundledEngineLibraryPath` in `engine_service_frb.dart`: `lib/libferman_api.so` on Linux, `ferman_api.dll` on Windows, `Contents/Frameworks/rust_lib_ferman.framework/rust_lib_ferman` on macOS). Never use flutter_rust_bridge's default loader: it tries a folder relative to the current directory first, and on macOS it looks for a framework cargokit does not build. When the engine cannot start, `bootstrap()` installs `UnavailableEngineService` and the app still opens.
- No synchronous engine calls on the build path (only `api_version()` is sync). Rendering and heavy work never run on the UI isolate.
- Generated files (`app/lib/bridge/`, `tokens.g.dart`, `*.g.dart`) are never edited by hand.

## Design fidelity

- Every screen matches its artboard in layout, spacing, typography, colour, icons, states and copy. Record any conflict or gap in [DESIGN_GAPS.md](../../docs/DESIGN_GAPS.md) and follow the option chosen there.
- Design copy that must change in the app: the licence is Apache-2.0, not GPL-3.0 ([G13](../../docs/DESIGN_GAPS.md#g13)); onboarding lists all four network uses ([G24](../../docs/DESIGN_GAPS.md#g24)); later-phase features are never marked "Included" ([G12](../../docs/DESIGN_GAPS.md#g12)).

## Brief §6 conventions

- **State and navigation:** Riverpod with code generation; go_router.
- **Design tokens:** `tools/tokens` reads the tokens in `design/` (`tokens/*.css` plus `ds-additions/fm-additions.css`, [G05](../../docs/DESIGN_GAPS.md#g05)) and generates `app/lib/design/tokens.g.dart`: plain `Ferman*Tokens` value classes that `app/lib/design/theme.dart` wraps in `ThemeExtension`s ([ADR 0012](../../docs/adr/0012-design-token-pipeline.md)). Widgets read tokens only through `context.ferman` (the `FermanTheme` extension, which resolves light and dark, density, reduced motion and the locale). Never hardcode colours, sizes, radii or durations in widgets: `tools/checks` `s6_literals` fails on such literals outside `app/lib/design/` and `app/lib/engine/`, and on reading a varying token set from its generated constant (`theme-bypass`).
- **Component library first:** before building screens, build the Ferman component library in `app/lib/design/components/`. It mirrors the design system 1:1: the same names, variants and states. Dart class names are the design-system names (`Button`, `IconButton`, …); only the `Fm*` building blocks such as `FmWindow` and `FmNumber` keep `Fm` ([ADR 0011](../../docs/adr/0011-flutter-state-navigation-components.md)). Screens are built from it. The widgets library has its own `Icon`, so every file that uses Ferman's `Icon` imports `package:flutter/widgets.dart` with `hide Icon`; Material and Cupertino are imported only in `app/lib/design/` and `app/lib/app/app.dart` (`s6_material_imports`).
- **Dialogs and popups:** custom popup-style widgets from the design system. Never the default Material or Cupertino dialog implementations (`showDialog`, `AlertDialog`, `showCupertinoDialog`, `showModalBottomSheet`, `showDatePicker`, `SnackBar`, Material `Tooltip`, `PopupMenuButton`). No GetX. `tools/checks` `s6_forbidden_api` enforces this list and its close relatives.
- **File pickers:** OS-native open, save and folder pickers through file_selector are the only proposed exception ([ADR 0018](../../docs/adr/0018-native-file-pickers.md), Proposed, [Q07](../../docs/QUESTIONS.md#q07)). Until the owner answers, M1 builds no picker and features that need one stay disabled with "Available in a future version". If M2 starts before an answer, the OS-native picker is used as the safest option ([brief §9](../../docs/BRIEF.md#9-how-to-work-in-every-later-session)) and flagged again in the M2 summary. All picker calls go through one `FilePickerService` with a fake for tests.
- **Tabs:** never `TabBarView`. Mode tabs and sidebar tabs are custom segmented controls over an `IndexedStack`, which preserves their state. There are eight mode tabs: View, Edit, Comment, Fill & Sign, Organize, Convert, Protect, Tools ([G09](../../docs/DESIGN_GAPS.md#g09), [Q05](../../docs/QUESTIONS.md#q05)).
- **Form validators** return `bool` and explicitly check null and empty values.
- **Localization:** gen-l10n with ARB files in `app/lib/l10n/`. English (`app_en.arb`) is the source and Turkish (`app_tr.arb`) is complete. Every user-facing string lives in the ARB files. Other languages fall back to English until translated. Never machine-translate silently; prepare for community translation through Weblate.
- **Casing:** Dart's `toUpperCase` is not locale-aware. Use `LocaleCasing` (`app/lib/l10n/casing.dart`, picked with `LocaleCasing.of(context)`), so Turkish shows "İMZALA"; `s6_casing` flags `toUpperCase` and `toLowerCase` outside `app/lib/l10n/`.
- **Formats:** locale-aware dates, numbers ("10,5 pt"), paper sizes and units, taken from the region setting, not the UI language, through `RegionFormat` (`app/lib/l10n/format.dart`) ([G34](../../docs/DESIGN_GAPS.md#g34)).
- **Right to left:** `EdgeInsetsDirectional` and `AlignmentDirectional` everywhere (`s6_directional` also flags `TextAlign.left` and `.right`, `BorderRadius.only` and `.horizontal`, `Border(left:, right:)` and `Positioned` with left or right). Mirror directional icons. Never mirror the PDF canvas.
- **Desktop:** custom title bars for macOS and Windows as designed (window_manager). Linux gets a custom title bar too: client-side decorations, caption buttons at the end, Ctrl shortcuts and Cancel on the left in dialogs ([G15](../../docs/DESIGN_GAPS.md#g15), [Q12](../../docs/QUESTIONS.md#q12)). Full keyboard shortcuts through Shortcuts and Actions, shown in tooltips and menus. Focus traversal in reading order. Semantics labels on every control.
- **Platform projects:** bundle identifier `io.github.kerembas.ferman` ([Q01](../../docs/QUESTIONS.md#q01)); minimums macOS 12.0 (universal), Windows 10 22H2 and 11 (x64, arm64), Linux best effort from Ubuntu 22.04 ([Q03](../../docs/QUESTIONS.md#q03)); copyright "Copyright The Ferman Authors" ([Q14](../../docs/QUESTIONS.md#q14)). Keep the macOS template's App Sandbox entitlement on until the owner answers [Q18](../../docs/QUESTIONS.md#q18), before M2.
- **Android 12+ splash** (mobile phase): use `background_image`.
- **Unfinished features:** features not implemented yet stay visible exactly as designed but disabled, with the tooltip "Available in a future version" and an entry in [BACKLOG.md](../../docs/BACKLOG.md).

## Fonts and icons

- Bundle IBM's unmodified static Plex TTFs in `app/assets/fonts/` with their OFL-1.1 licence files: Plex Sans 400/500/600 and Italic 400, Plex Serif 400, Italic 400 and 600, Plex Mono 400/500, and Plex Sans Arabic, Plex Sans Hebrew and Plex Sans Devanagari 400/500/600 (the last two approved in [Q08](../../docs/QUESTIONS.md#q08)). `tools/fonts` fetches them and pins their SHA-256. Never subset, rename or modify them (Reserved Font Name "Plex"). No handwriting or similar-font faces until Q08 groups 3 and 4 are answered.
- The Arabic, Hebrew and Devanagari fonts carry ASCII and Latin-1 but not Turkish letters (Latin Extended-A) or ế, so no script font comes first in a chain: every UI language but CJK uses the `--font-ui` order, Plex Sans first ([ARCHITECTURE.md §11.5](../../docs/ARCHITECTURE.md#115-fonts-in-the-ui), [G64](../../docs/DESIGN_GAPS.md#g64)). Build chains with `FermanFontFamilies.uiChain`.
- CJK falls back to system fonts ([ADR 0013](../../docs/adr/0013-fonts-and-icons.md)). Set the text locale on text styles so Han characters take the right regional forms.
- Never use the design's woff2 subsets or its runtime Google Fonts import. The app never fetches fonts.
- Icons come from the design's exact path data (229 icons), generated by `tools/icons` and painted by the Icon widget's `CustomPainter` through path_parsing at a 1.5 px stroke (overridable). The SVGs in `app/assets/icons/` are the exported, provenance-tracked set and are not loaded at run time. Exactly 8 icons mirror in right to left (`IconName.directional`): arrow-left, arrow-right, chevron-left, chevron-right, undo-2, redo-2, skip-back, skip-forward. The Lucide ISC and Feather MIT notices (`LICENSE-lucide-0.460.0.txt`, `LICENSE-lucide-1.56.0.txt`) and every other licence text appear through Flutter's LicenseRegistry.

## Tests

- `flutter analyze` and `dart analyze --fatal-infos` are clean. Widget tests for every component and screen.
- alchemist goldens for every implemented screen in light and dark × en, tr and ar, with the real bundled fonts loaded. Goldens are generated and compared on the Linux CI runner only: golden tests carry the `golden` tag (`app/dart_test.yaml`), and macOS and Windows run `flutter test --exclude-tags golden`. Every golden test also passes `skip: !isGoldenHost` (`app/test/helpers/golden_config.dart`): off Linux alchemist's test variant has no values, and flutter_test fails the file while loading it, before the tag filter applies. On Linux the goldens need `fonts-dejavu-core` and `fonts-noto-cjk` (the macOS key symbols and CJK names; `flutter_test_config.dart` appends them to the UI font chains through the test-only `FermanFontFamilies.debugExtraFallback`, which the app never sets). Window goldens go through `test/helpers/window_golden.dart` (`windowGoldenTest`), 1440 × 900 at 1x, named `<screen>_<mac|win>_<light|dark>_<en|tr|ar>`, the contract with `tools/design-refs/compare-map.json`.
- Compare goldens against the artboard renders in `build/design-refs/` (made by `tools/design-refs`). Never commit `build/design-refs/` or golden failure output.
- `tools/design-refs` runs offline: the runtime scripts and fonts come from npm packages pinned in its lockfile and are served locally, and every other network request fails the run. Capture rule: a product board is the first `.fm-root` inside the element with the id `<id>`, or that element itself when it carries `.fm-root` (the sidebar boards `a2-3p` to `a2-3x`); the fix boards `f1` to `f6a` are the whole element with the id (the `section` for `f1` to `f6`, the nested `div` for `f4a`, `f4b` and `f6a`). Each board renders on its own fresh page. It reads `design/` and never writes to it.
- `app/integration_test/app_test.dart` is the only integration-test file (Linux desktop cannot launch the app a second time for a second file); add new cases to it. `flutter test integration_test -d <system>` runs it in debug mode; timings come from profile mode: `flutter drive --profile -d <linux|windows|macos> --driver=test_driver/integration_test.dart --target=integration_test/app_test.dart`.
- `tools/tokens`, `tools/icons`, `tools/l10n` and `tools/checks` have their own tests (`dart test`), and `dart run tokens --check`, `dart run icons --check` and `dart run l10n --check` fail on stale generated files.
