1.9fOut of memory — one tab closedmacOS · Light · {{ L.name }}G28

G28 · When a document runs out of memory or fails in a way Ferman can’t recover from, only its tab closes. The toast says so in plain words at the bottom end of the canvas, above the status bar, and the other documents keep working (ADR 0010). Try again reopens the file.

1.13Open file — system open panelmacOS · Light · {{ L.name }}G25G26
System open panelDrawn by macOS (NSOpenPanel), Windows (IFileOpenDialog) or the Linux desktop portal, in the system’s language. Ferman asks for PDF files and allows several at once.

G25 · G26 · From M2, ⌘O, “Open file…” and “Open a PDF” hand off to the system open panel (ADR 0018, pending Q07). Each chosen file opens as a new active tab. A file sent from Finder, Explorer or the file manager (double-click, Open with, Dock, taskbar) does the same in the running window, one instance per user; a file that is already open focuses its tab instead of opening twice; a cold launch with a file skips Start and opens the document.

1.10 – 1.12 · Tabs, saving and recovery

1.10aMany documents — tab overflowmacOS · Light

Tabs shrink to 112 px, then the rest move into “+4”. Hidden tabs with unsaved changes carry the dot here too. ⌃Tab cycles through all ten in order, ⌘1…⌘9 jump. Names never truncate in the menu.

1.10bClose with unsaved changesmacOS · Light

macOS order: “Don’t save” at the start, Cancel then Save at the end; Save is the default (Enter), Esc cancels, ⌘D is “Don’t save”. Windows shows Save, Don’t save, Cancel from the left.

1.11Save as — formats and optionsmacOS · Light

⇧⌘S. Each format says what it changes. “Save a copy” is a checkbox here and also its own command (⌥⌘S).
