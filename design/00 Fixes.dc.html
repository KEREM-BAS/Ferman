00 · Fixes to the current editor kit

Six problems found in the editor kit, fixed in the design system before any other screen was drawn. Each fix lives in ds-additions/fm-additions.css as a token or a patch to an existing component, so every artboard in this project already uses the corrected version.

FIX 1

The text-frame label never covers content

The font · size tab sat on top of the line above the selected block. It now attaches outside the frame and picks the first free side: above, then below, then the page margin.

BeforeLabel covers the IBAN line
AfterNo room above, so it flips below
AfterHeading above, IBAN below, so it moves into the margin

1 · Above. Default when the 20 px above the frame are empty (label 18 px + 2 px gap). Starts at the frame’s start edge; in right-to-left documents it starts at the right.

2 · Below. Used when text, an image, a mark or the page edge is directly above. The tab shape flips so its flat edge touches the frame.

3 · Margin. When neither side is free, the label sits beside the first line, outside the text column. It can extend past the page edge; it never overlaps text, handles or other marks.

TextEditBox · new attribute data-meta-placement = above | below | margin · token --editbox-meta-h: 18px · placement is recalculated while the frame is dragged or resized.

FIX 2

The missing-glyph warning appears once

The same sentence was shown under the font field and again in the callout. Now the font field carries only a small amber icon; the sentence and the way out live in the warning callout.

BeforeSame warning twice
Text block
This font has no ‘ğ’. Ferman will use a similar font for this character.
AfterIcon in the field, message once
Text blockEdited
This font has no ‘ğ’. Ferman will use a similar font for this character.
Choose a font…Keep as is

Font field. Amber border and a 14 px triangle before the name. Tooltip: “Missing ‘ğ’. Details below.” Screen readers hear “Font, Garamond Premier Pro, warning: missing character”.

Callout. The only place with the sentence. Names the exact character and what Ferman does, then offers “Choose a font…” (opens the substitution picker, 3.3) or “Keep as is”.

On the page. The glyph keeps its amber wavy underline and the frame tab turns amber.

FontPicker · new state [data-fm-glyph-warning] · the `warning` prop is reserved for fonts that are not installed.

FIX 3

Edited text and highlights look different

Edit marking used a tinted fill, too close to a highlight annotation. Edited text now gets a subtle dotted underline and a bar in the left margin, both in the accent ink. Highlights keep the translucent marker colours. Edit marking never uses yellow.

Edited text · Ferman’s own marking
Kiracı, aylık kira bedeli olan 19.500 TL’yi her ayın beşinci gününe kadar kiraya verenin hesabına öder.
Dotted 1.5 px underline + 2 px margin bar, --edit-mark (ink 600, 7:1 on white). Only on the lines that changed. Shown while “Mark edited text” is on; never saved into the PDF or printed.
Highlight · an annotation in the file
Kiracı, aylık kira bedeli olan 18.500 TL’yi her ayın beşinci gününe kadar kiraya verenin hesabına öder.
Translucent marker colour multiplied onto the text (--annot-yellow, green, blue, pink, orange). Saved in the PDF, listed in Comments, printed by default.
Both on the same line
Kiracı, aylık kira bedeli olan 19.500 TL’yi her ayın beşinci gününe kadar kiraya verenin hesabına öder.
The two never compete: one is a line, the other a fill. A highlighted edit shows the fill under the dotted line.
FIX 4

Save state is always honest

With unsaved edits the Save button is enabled, the tab shows a dot and the status bar says “Unsaved changes”. After saving the button is disabled, the dot goes away and the status bar says “Saved on this device · 14:32”.

F4aMain editor — unsaved changesmacOS · Light

Save is primary and enabled (⌘S). Tab: dot replaces the close button; screen readers hear “Kira sözleşmesi.pdf, unsaved changes”. Status bar item is a polite live region.

Save is disabled with the tooltip “No changes to save”. Edit marks stay until the document is closed, so you can still review what changed in this session.

FIX 5

Thumbnail badges have a legend

One unexplained corner dot became five defined badges, stacked at the thumbnail’s top-end corner in a fixed order. The info button in the Pages header opens the legend; each badge has a tooltip.

Tooltip on a badge
Shown at 2× for legibility. Badges are 16 px chips (8 px dot for Edited) with 10 px icons at 2 px stroke. Order is fixed: edited, comments, form fields, signature, warnings. Badges are focusable inside the thumbnail with the arrow keys and announce their tooltip.
Rules

Edited: accent dot (--edit-changed, now ink 600). Comments, form fields and signature: neutral chips on white. Warnings: the only coloured chip, amber triangle on amber tint.

Badges sit on the page preview because the page is white in every theme, so the chip colours never change with theme.

The page text lines step aside (inline-end inset 24%) so badges never cover the preview.

FIX 6

Windows window chrome

Same layout and components; the platform layer changes. Caption buttons (minimize, maximize, close) sit flush at the top-right, 46 px wide, close turns red on hover. No traffic lights, 8 px window corners, shortcuts use Ctrl, Alt and Shift.
